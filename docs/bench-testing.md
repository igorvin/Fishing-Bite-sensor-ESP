# Стендовый выпуск: C3 + LSM6DS3 и XIAO S3

[Состав выпуска и результаты программной приёмки](bench-release.md). Это кандидат алгоритма для измерений на столе и удилище. Компиляция и синтетические тесты не доказывают обнаружение реальных поклёвок, дальность или автономность. Существующий хаб SH1106 менять/перепрошивать для этого выпуска не требуется: пакет остался packed 22 байта, eventType 1/2/3.

## Что изменено

- Признак Dynamic XYZ — длина вектора `a − оценка тяжести`, в отличие от Legacy `abs(|a| − baseline)`. Оба значения видны одновременно; режим выбирается явно.
- Порог нового алгоритма хранится отдельно в `dynamicThresholdG`; прежний `deltaG` сохранён только для Legacy. Старая БД не стирается и прежний порог не выдаётся за эквивалент нового.
- Проверяется реальная I²C-транзакция, длина XYZ burst и Data Ready LSM6DS3. Диапазон 2 g, частота IMU 104 Гц; гироскоп выключен, поскольку этот кандидат использует только акселерометр.
- Калибровка шума занимает 2 секунды без блокирующих delay. Движение/ошибка датчика отвергают её. Измеренный шум сохраняется, но при каждом запуске требуется новая проверка покоя; сохранённый шум сам по себе не даёт READY.
- После команды ARM требуется устойчивый покой 1,5 с. Перемещение переводит в SUPPRESSED; 1,5 с покоя в новом положении и ещё 1,5 с стабилизации возвращают ARMED. Это начальные стендовые времена, не доказанные оптимальные параметры рыбалки.
- Ручной DISARMED и FAULT автоматически не включаются. После ошибки IMU и восстановления требуется явная команда ARM; первичная калибровка выполняется заново.
- Импульсы/звук неблокирующие, обслуживаются и при DISARMED/FAULT. У пассивного зуммера 100% уровня — 50% duty носителя 3 кГц, не постоянный HIGH. Фактическую громкость проверить на установленном излучателе.

## Подключение стенда (с 2026-11-22: одна кнопка на D1)

| Функция | XIAO D-pin | C3 GPIO | S3 GPIO |
|---|---|---:|---:|
| Кнопка ARM / сон / пробуждение, active LOW, на GND | D1 | 3 | 2 |
| VBAT через существующий делитель 100k/100k | D2 | 4 | 3 |
| IMU SDA | D4 | 6 | 5 |
| IMU SCL | D5 | 7 | 6 |
| Зелёный LED / драйвер | D7 | 20 | 44 |
| Красный LED / драйвер | D8 | 8 | 7 |
| Пассивный buzzer / драйвер | D9 | 9 | 8 |

Пользователь перенёс кнопку с D6 на D1, потому что D6 не будит C3/C6/S3 из глубокого сна. D0 (бывший power latch) и D6 больше не используются. Внешний подтягивающий резистор не нужен: на стенде работает внутренний pull-up, во сне его включает драйвер сна. Common GND обязателен; мотор и мощный излучатель не подключать прямо к GPIO.

Плата v4 (`kicad/kicad_bite`) использует отдельный профиль `bite_v4_s3`: кнопка D1 (внешний R3 10k), INT1 IMU на D3 (пока не используется), VBAT на D0, красный LED D8, зелёный D9, buzzer D10.

## Кнопка и глубокий сон

| Действие | Результат |
|---|---|
| Удержать 1–3 с и отпустить | короткий писк на 1 с, после отпускания ARM ↔ DISARM |
| Удержать ≥ 3 с и отпустить | длинный писк на 3 с, после отпускания охрана снимается, настройки записываются, IMU в power-down, радио выключено, deep sleep |
| Во сне коснуться < 1 с | плата сразу засыпает снова (счётчик `short_wakes`) |
| Во сне удержать ~1 с | пробуждение, писк, калибровка 2 с, DISARMED; хаб регистрирует датчик заново |
| DISARMED 3 мин без нажатий, USB-команд и клиентов AP, CSV выключен | сон `idle` |
| Три замера подряд VBAT < 3.30 В | событие 3 хабу (если была охрана) и сон `battery` |

USB: `status` показывает `wake`, `sleeps`, `short_wakes`, `last_sleep`, `button`, `vbat`; `sleep` усыпляет датчик (только при снятой охране). Во сне USB-порт пропадает, после пробуждения появляется снова. Ток сна по USB не измерить: его нужно мерить мультиметром от батареи.

**Проверено 2026-11-22 на стендовой C3 (питание только USB):** ARM/DISARM кнопкой, сон по удержанию, короткое касание не будит, пробуждение по удержанию 1 с, сон по простою через ~180 с, после пробуждения IMU исправен и хаб снова регистрирует датчик. Не проверены: ток сна, работа от батареи, защита по низкому VBAT, плата v4.

USB CDC включён для C3/S3, чтобы Serial не занимал UART D6/D7 (D7 — LED). Не подключать внешний UART к этим линиям одновременно с существующей схемой.

## Сборка и загрузка

Прямые зависимости и platformio/espressif32@8.0.0 закреплены в platformio.ini (Arduino-ESP32 3.3.12). Для команд нужен установленный PlatformIO Core CLI: установить его или активировать окружение PlatformIO так, чтобы `pio --version` выполнялась в текущем терминале. Для host-тестов/replay также нужны Python 3 и C++17 compiler (`c++` либо переменная `CXX`). Первая сборка скачивает платформу и библиотеки, поэтому нужен доступ к registry. Команды выполняются из корня проекта:

```sh
pio run -e xiao_esp32c3
pio run -e seeed_xiao_esp32s3
```

Сначала выбрать правильную плату и порт. Команды **для пользователя**, автоматически этот выпуск ничего не загружает:

```sh
pio run -e xiao_esp32c3 -t upload --upload-port <PORT>
# Либо будущий XIAO S3, не C3-бинарник:
pio run -e seeed_xiao_esp32s3 -t upload --upload-port <PORT>
pio device monitor --port <PORT> --baud 115200
```

Не делать erase-flash/uploadfs для обычного обновления: это может удалить сохранённую конфигурацию. Прошивка создаёт LittleFS только если её раздел целиком стёрт (все байты FF). Непустой раздел с ошибкой монтирования не форматируется автоматически: показывается FS ERROR, настройки работают только в RAM до восстановления. Существующий `/config.db` используется без массового сброса. После смены partition layout требуется отдельная проверка совместимости; этот выпуск layout не меняет.

Firmware.bin — образ приложения, его нельзя бездумно записывать по адресу 0. Для ручной прошивки пользоваться либо PlatformIO upload, либо подготовленным factory image/его manifest с верными offsets для конкретной платы.

## Первая проверка

1. Закрепить IMU жёстко и не трогать 2 с после старта. На C3 стенде проверять по USB. Открыть AP с прежним именем/паролем либо `BiteSensor` при первой установке; веб — `http://192.168.4.1`.
2. Status: проверить состояние и результат калибровки. Включить «Подробности» для IMU OK, FS OK, PWM OK. Состояние после загрузки — DISARMED, даже если старый `armedSw` был true. Это явный безопасный запуск стендового выпуска.
3. Перейти Status/Sensor/Settings без F5, переключить Dynamic/Legacy и suppression: зависимые поля должны сразу перестроиться.
4. В Sensor выбрать Dynamic XYZ, начать с порога 0,020 g, noise multiplier 4. Это стартовая настройка, не универсальный оптимум. **Меньше порог — выше чувствительность.** Рабочий порог Dynamic — максимум ручного порога и `noise × multiplier`; если шум повышает его, интерфейс сообщает об этом.
5. Отдельно нажать «Калибровка шума», 2 с держать неподвижно. Затем повторить с движением: ожидается rejected, не ложное success. После отказа охрана снята; повторить спокойно и поставить заново.
6. Проверить «Тест сигнала» при DISARMED: короткий локальный звук/LED, выключение по времени, без радиопакета. В FAULT/Calibrating/SUPPRESSED/Settling тестовый alarm не является доказательством готовности детектора.
7. ARM: SETTLING → ARMED, зелёный LED только в ARMED. Переключатель охраны синхронизируется с желаемой охраной при обновлении данных; фактическую готовность проверять по состоянию (SETTLING ещё не ARMED). Слабые повторяемые толчки дают видимые XYZ/Dynamic и событие, если пересекают рабочий порог достаточное время. Уменьшать порог постепенно, одновременно проверяя ложные тревоги в покое.
8. Поднять/повернуть удилище: SUPPRESSED → SETTLING → ARMED в устойчивом **новом** положении. DISARM вручную и подождать: само включаться не должно.
9. Если инициализация IMU успешна, но первого Data Ready нет, через 150 мс ожидается FAULT; повторная инициализация не чаще чем через 2 с после отказа. После появления свежих кадров — калибровка и DISARMED без автоматического ARM.
10. Отключить IMU во время охраны: ожидается FAULT, выходы выключены. Вернуть IMU: ограниченные попытки повторного обнаружения; после калибровки DISARMED, нужна ручная постановка. Проверка адреса не заменяет этот physical test.
11. Изменить порог/режим, дождаться Saved, перезапустить: настройки должны сохраниться. Новый шум будет измерен после старта. При FS ERROR не считать сохранение успешным.

В Settings сеть меняется только кнопкой «Проверить, сохранить сеть и перезапустить». До неё — черновик. Неверный SSID/password/MAC не применяется. MAC только 6 октетов по две hex-цифры, unicast/nonzero. Разрешён пустой пароль AP для совместимости стенда; открытый AP и библиотечные OTA/file endpoints не следует считать защищённым производственным режимом. Полная политика доступа и новый радиопротокол остаются следующим этапом.

## Мобильный интерфейс

В меню три страницы: «Статус», «Датчик», «Настройки». На «Статусе» постоянно видны состояние, актуальный результат калибровки, приблизительная батарея, ESP-NOW, калибровка, тест, охрана и Serial CSV. «Подробности» изначально закрыты и раскрывают прежние технические показатели, включая сырое напряжение АЦП и последнее сообщение операции. Последнее сообщение — история, а актуальный исход калибровки показывает отдельная строка «Калибровка» без процента от отклонённой попытки. Недостоверное для одиночной Li-ion напряжение не превращается в процент заряда; подключение аккумулятора автоматически не определяется. «Готов» у ESP-NOW не подтверждает приём хабом.

Подписи и значения переносятся в пределах ширины телефона. На странице «Датчик» значение порога можно нажать для точного ввода; диапазоны и смысл настроек сохранены. Наклон UP / крен TILT: нулевой угол отключает соответствующую проверку.

## Запись слабых движений

Status → Serial CSV. Записываются все новые выборки (до 104 Гц), не только 20-Гц обновление интерфейса. Пример заголовка:

```text
ms,ax_g,ay_g,az_g,dynamic_g,legacy_g,noise_g,threshold_g,state,event,mode
```

Включить захват, сохранить вывод Serial в CSV, держать датчик спокойно не менее 5 с, затем давать повторяемые слабые толчки с паузами. `mode=0` Dynamic, `1` Legacy; event 1/2 — логические выходы детектора, не отдельные строки каждого последующего миллисекундного состояния. Счётчик Events считает начало движения; Pulses включает также повторные и тестовые импульсы.

Буфер Serial ограничен 2048 байт и отдаётся только когда транспорт готов; при перегрузке отбрасывается **целая строка**, растёт CSV dropped. Никакая выборка не пишется во flash. При drops/разрывах timestamp такая запись не доказывает точную задержку. Фактические Hz/gaps/ошибки видны в веб. Gaps считает разрывы между свежими выборками более25мс (один длительный разрыв учитывается один раз); отсутствие свежих данных более150мс переводит в FAULT. USB host может приостановить приём; открытие монитора и диагностика не должны остановить сам детектор.

Режим CSV удерживает стенд от автоматического сна. При обычной охране AP закрывается спустя 2 мин, ESP-NOW остаётся активным. Если CSV-форма недоступна после закрытия AP, снять охрану кнопкой и открыть AP заново; захват по USB при этом можно продолжить.

## Воспроизведение на компьютере

Python стандартной библиотеки и C++17 compiler, дополнительных Python packages нет:

```sh
python3 tools/run_host_tests.py
# После PIO сборки xiao_esp32c3, которая устанавливает pinned зависимости:
python3 tests/test_storage_integration.py
python3 tools/replay_csv.py tests/fixtures/weak_transverse.csv > dynamic.csv
python3 tools/replay_csv.py tests/fixtures/weak_transverse.csv --mode legacy > legacy.csv
python3 tools/replay_csv.py capture.csv --threshold 0.010 > replay.csv
```

Replay использует **то же SensorCore.h**, что прошивка, но задаёт фиксированную конфигурацию: 2-секундная quiet calibration, запрос ARM через 3 с от первой записи и 1,5 с settling. Поэтому нужен спокойный начальный фрагмент минимум 5 с. Включения/изменения UI из прошлой сессии автоматически не восстанавливаются; это сравнение алгоритмов на одинаковых XYZ, не побитовое воспроизведение всей MCU/радио-сессии. `--arm-delay` задаёт момент запроса ARM относительно первого sample. Порог Legacy и Dynamic имеют разный физический смысл: сравнивать также уровень ложных тревог, не только количество срабатываний.

Fixture `weak_transverse.csv` — 701 синтетическая выборка с двумя импульсами X=0.1g при Z=1g. При default thresholds replay выдаёт 2 события Dynamic и 0 Legacy. Это демонстрация математической слепой зоны старого признака, **не процент реальных обнаруженных поклёвок**.

## Что записать для следующего этапа

Для каждого крепления/положения: 5–10 мин фона, одинаковые слабые толчки/имитации леской разных направлений, поднятие/возврат, номер платы и параметры порога/шума. Отдельно пометить ложные тревоги и пропущенные имитации. Затем на водоёме независимая разметка реальных событий. Дальность, фактическую батарейную ёмкость/ток, ADC против мультиметра, громкость/тип buzzer, latch и wake проверять физически.

Radio остаётся без application ACK: MAC success не гарантирует показ на хабе. Low-battery уведомление теперь повторяется с редким периодом, но надёжную доставку с ACK этот выпуск не обещает. По voltage-derived SOC показывается приблизительный процент, не ёмкость аккумулятора.

При ошибке чтения существующего `/config.db` настройки работают только в RAM: ручное сохранение, библиотечный autosave и сохранение калибровки не меняют исходный файл. Для проверки сохранить копию/хеш файла до старта, изменить настройку и провести калибровку, подождать более 10 с и сравнить байты. Новая отсутствующая БД создаётся штатно.

Storage integration использует установленный `.pio/libdeps/xiao_esp32c3/GyverDB/src/GyverDBFile.h`: исходные begin/tick/update/destructor компилируются с fake platform/FS и production ConfigDatabase. На чистом checkout сначала выполнить указанную PIO сборку C3; standalone core suite этого header не требует. `python3 tests/test_storage_integration.py --baseline` намеренно воспроизводит отказ исходного незащищённого GyverDBFile.

## HU02: разовая регистрация

Алгоритм детекции/пины/CSV и настройки сохранены. Добавлены совместимые стартовые control-пакеты: [протокол и USB-команды](startup-registration.md). У датчика `status` не меняет охрану; `register` — явная диагностика только Disarmed, без события поклёвки; `peer <MAC>` только Disarmed с проверенной записью существующих ключей. При недостоверном измерении батареи (`vbat` вне2.5…4.5V) low-battery не отправляется, в том числе на USB-стенде. [Схема питания](power-and-wiring.md).
