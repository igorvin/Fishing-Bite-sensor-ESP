# Разовая регистрация HU02

Это подтверждение обмена при запуске, **не постоянный статус подключения**, не heartbeat и не подтверждение доставки поклёвок. Прежний 22-байтный пакет событий 1/2/3 сохранён. Датчик и хаб используют один переносимый заголовок `shared/StartupRadio.h`.

## Формат

Отдельный упакованный little-endian control packet — 36 байт: magic `FBS1` (uint32), version 1, kind (DISCOVER 1 / ANNOUNCE 2 / ACK 3), flags (bit0 — battery valid), reserved byte, hubSession uint32, sensorSession uint32, name[16], battery uint8, node uint8, reserved2 uint16. Остальные flag/reserved-биты должны быть нулями. Размер проверен static_assert; декодер проверяет точную длину, magic/version/kind, диапазоны и корректность ограниченного UTF-8. Пакет другой версии игнорируется, не трактуется как тревога.

- DISCOVER содержит ненулевую сессию хаба, остальные служебные поля нулевые.
- ANNOUNCE содержит ненулевой идентификатор запуска датчика. hubSession=0 допускается при его самостоятельном включении; иначе должен совпасть с текущей сессией хаба. При неизвестном заряде flags/battery=0. Имя не читается за 16 байтами.
- ACK связывает hubSession и sensorSession, node=1…8. Датчик принимает его только от сохранённого MAC своего хаба и только для текущего запуска/ожидаемой сессии.

Хаб отправляет до трёх DISCOVER при запуске в пределах 8 с, затем прекращает опрос. Датчик с разрешённым радио отправляет ANNOUNCE только настроенному хабу, максимум три попытки с интервалом 700 мс на каждую стартовую серию. Собственное включение и впервые полученная новая сессия хаба — отдельные ограниченные серии. ACK останавливает попытки. Повтор одного DISCOVER session и последние четыре виденные сессии не запускают новые серии, включая DISCOVER после уже полученного ACK; новый запуск хаба может вызвать одну новую ограниченную серию. Нет постоянных повторов после исчерпания. Все peer/send/регистрационные действия выполняются в loop; callback только проверяет и кладёт ограниченную копию в защищённую очередь.

Реестр хаба хранит до 8 MAC в RAM. ANNOUNCE обновляет имя/последний известный заряд и подтверждается ACK, но **не создаёт поклёвку, запись журнала, вибрацию или пробуждение экрана**. Прежнее допустимое событие тоже учитывает отправителя. Число означает учтённых после текущего запуска, а не число доступных сейчас. Имя не идентификатор. Это не защищённое криптографическое сопряжение; сохранённый MAC не заменяет аутентификацию.

## Настройка и проверка через USB

При старте хаб печатает свой действительный MAC. В датчике радио по-прежнему включается явно в существующих веб-настройках; автоматического выбора нового хаба нет. Для стенда добавлены команды:

- Хаб `status`: состояние модели экрана, radio/OLED-ready, число удилищ/истории, control_rx/control_tx. `summary`, `list`, `history`, `service` — явный просмотр на 30 с; тревога имеет приоритет.
- Датчик `status`: radio, registered, attempts, node, control_rx/control_tx, состояние детектора/IMU. `registered=1` означает только полученный стартовый ACK.
- Датчик `peer AA:BB:CC:DD:EE:FF`: только при снятой охране, с валидным unicast MAC и доступным хранилищем. Сохраняет существующие поля hubMac/espNowEn, не меняет другие настройки; при ошибке записи текущая конфигурация не переключается.
- Датчик `register`: только при снятой охране; ограниченная диагностическая повторная регистрация. **Не отправляет событие поклёвки**, не доказывает чувствительность IMU или доставку тревоги.

Без обновления датчика хаб продолжает принимать старые тревоги, но не получает стартовый ANNOUNCE от старой прошивки. После обновления нужны проверка именно двух ролей/портов и физическая приёмка по `hub-testing.md`. Реальные MAC не записываются в публичные примеры.
