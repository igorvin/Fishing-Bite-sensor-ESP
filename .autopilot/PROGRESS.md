# Fishing Bite Sensor — текущее состояние

Рабочая ветка: `codex/sensor-bench-sensitivity`.

Инструкции: `docs/bench-testing.md`, `ESP_HUB/README.md`, `docs/hub-testing.md`.

## Выполнено

- Датчик: 29 host-тестов; C3/S3 собираются. Прошит физический C3 с LSM6DS3, USB XYZ реально получены. Мобильный интерфейс пользователь принял на телефоне.
- HU02 по последнему выбору: компактный счётчик/значок батареи на старте 8 с, затем OLED off; свежая тревога будит. Полный список/журнал только явными USB-командами, без автоперелистывания. Кнопок нет.
- HU01: bounded очередь RX, проверка 22-байтного пакета/UTF-8, идентичность по MAC, приоритеты тревог, объединение продолжений, ограниченные импульсы мотора, восстановление OLED независимо от запуска радио.
- F2: освобождение ресурсов драйвера перед повторным OLED begin и окно продолжения 2500 мс для sensor repeat до 2000 мс с задержкой выборки. Независимое повторное ревью закрыло оба замечания.
- Текущий HU02: 36 тестов хаба с ASan/UBSan и 29 датчика; чистый клон получил 8 actual-renderer кадров и собрал все 4 профиля C3/S3. Ограниченная аппаратная проверка USB-пары выполнена; полевые замеры и вибрация остаются открытыми.

## Договорились

- Стенд датчика — XIAO C3 + LSM6DS3; будущий датчик — XIAO S3. Крепление на средней части бланка, компактный корпус/малый аккумулятор.
- Временно подавлять тревоги при перемещении и возвращаться после стабилизации; ручные Disarmed/Fault сами не включаются.
- Хаб — существующий SH1106 128×64; без кнопок. Русский монохромный экран, MAC только сервисный/USB.
- Старый пакет 22 байта сохранён; нельзя выдумывать heartbeat, связь, удалённую охрану или подтверждённую доставку.
- C6 optional: непригодность не доказана, физическая работа не заявляется.
- Пользователь разрешил upload и попросил без бэкапов. Перед hub upload идентифицировать именно хаб; ранее подключённая C3 была датчиком.
- Не трогать пользовательские .DS_Store/.vscode, optional-файлы и ESP_HUB/low-power*.

## Не доделано

- HU02 обе C3 прошиты с проверкой ролей и hash; radio/OLED-ready/IMU/startupregistration и ON→OFF подтверждены. Остались физическая поклёвка/вибрация, вид реального экрана и reconnect/батарейная приёмка по `docs/hub-testing.md`.
- Проверка на удилище/рыбалке: слабые поклёвки, ложные сигналы, ветер, дальность, latency, ток и автономность. Стендовые касания не доказывают полевую эффективность.
- Надёжная доставка alarm ACK/sequence/heartbeat и защита радиопротокола требуют отдельного изменения обеих прошивок. Разовая регистрация HU02 не подтверждает непрерывную связь/охрану и не гарантирует доставку поклёвки.
- Нужны фактические схемы питания/выходов и параметры аккумуляторов. GPIO без схемы не переназначать.
- GitHub push ранее заблокирован авторизацией; локальные коммиты сохранены, публикация не подтверждена.

## Известные ограничения

- Датчик: при малом изменении положения получалась постоянная тревога; отключение/включение охраны сбрасывало её. При UP/TILT 5° восстановление подтверждено, события до/после подавления остаются. Это пока не исправлено.
- Датчик: скриншот rejected calibration не был успехом; старое сообщение о сохранении может оставаться в подробностях, основной статус теперь показывает фактический исход.
- D6 не подходит для текущего deep-wake; сон датчика заблокирован до проверки схемы. Открытый AP/Settings OTA/files и питание latch отдельно не доведены.
- Хаб: реестр 8 MAC и журнал 12 эпизодов только RAM, после рестарта номера/история сбрасываются. Лимиты — настраиваемые defaults, количество удилищ пользователь не уточнил.
- Хаб: при заполнении RX24 новый пакет отбрасывается со счётчиком; гарантии доставки нет. При уже идущем моторе OLED может ждать до 800 мс.
