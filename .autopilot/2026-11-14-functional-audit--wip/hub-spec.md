# HU01 — Комбинированный дисплей и переработка хаба

Запрос: «начал перерабатывать полностью хаб ... полностью фокус на дисплей». Выбор2026-11-17: «сочетание».

**Требования:** G17, G18
**Зона:** ESP_HUB/src, ESP_HUB/include, ESP_HUB/tests, ESP_HUB/tools, ESP_HUB/platformio.ini, ESP_HUB/README.md, docs/hub-*
**Модель:** сильная
**Ревью:** нет (T0, одно итоговое ревью)

## Реализация и приёмка

SH1106 128×64: список удилищ в ожидании; при поклёвке крупный номер/имя и тип события; журнал последних событий отдельно. Русские подписи и UTF-8 имена, ровные поля, отсутствие пересечений. Ясно различать батарею хаба и последнюю известную батарею датчика; недостоверное напряжение отображать неизвестным. MAC только в сервисном экране/Serial.

Portable модель с ограниченной памятью: до8отправителей по MAC,3строки на страницу, журнал12эпизодов. Имена не являются идентификатором. Переполнение предсказуемо и со счётчиком. Пустой реестр честно показывает ожидание без выдуманных подключений/ARM/RSSI/heartbeat. Отсутствие поклёвок не означает потери связи.

Количество удилищ и кнопки уточняются у пользователя; независимую часть строить сразу. Пока базовый режим без кнопок: автосмена список/журнал около8s, тревога всегда вытесняет навигацию. Serial-команды list/history/service/help для стенда; GPIO кнопки не назначать. Ответ пользователя применить до завершения.

Сохранить22байтныйпакет, sensorкод не менять. Разделить portable модель/таймеры, проверку пакетов, concurrent-safe очередь и отрисовку. RX callback без String/I2C: только bounded проверка/копия в очередьFreeRTOS. Проверять длину/type1..3/battery0..100/finite nonnegative delta; имя16байт без чтения за границей,UTF8 fallback. НесколькоMAC не перезаписывают single shared slot. Первое событие и продолжения одного эпизода объединять в журнале, не перезапускать полный экран/мотор на каждом пакете. Приоритет поклёвки выше lowbat; политика нескольких активных тревог должна сохранять видимость остальных событий.

Мотор/LED неблокирующие, импульс ограничен по длительности. СохранитьGPIO D1/D2 иI2C D4/D5. Без схемы новыепины не добавлять. ОтказOLED не блокирует радио/выходы; ограниченный timeout/retry. dim60s/off120s, просыпается от события; battery refresh и автостраницы не отменяют dim/off.

Единая закреплённая совместимая платформа и зависимостиC3/S3. C6 не удалять как «неподходящий» без доказательств, можно оставитьoptional/unverified; зависимости IMUдатчика хабуне нужны. Для русских шрифтов разрешён U8g2_for_Adafruit_GFX с проверенной и закреплённой версией; официальный upstream https://github.com/olikraus/U8g2_for_Adafruit_GFX поддерживаетGFXиcyrillicfonts. Не требуется обновлять всё на latest.

Meaningful tests производственного portable кода: плохиепакеты/16байтноеимя/UTF8;несколькоMACсодинаковымиименами;очередь/overflow;продолжения/приоритет;rollover;sleep/wake. Нужны actualrendererкадры128×64 для пустого/списка/тревоги/журнала/длинногоимени. Не выдаватьHTMLперерисовку за actualrenderer. СборкиC3/S3 и sensor29/0.

## Ограничения

Heartbeat/ACK/подтверждённаясвязь/удалённаяохрана/дальность/автономность сейчас не реализуются и не заявляются. Исходный sensor не трогать. Текущая подключённаяC3 была датчиком: НЕ загружать hubfirmware автоматически. Не коммитить/пушить/прошивать.

Пользовательские .DS_Store/.vscode/.gitignore.optional и ESP_HUB/low-power* не трогать. RootREADME можно менять только точечной ссылкой на новыйhubguide. .autopilot правит root.

## Уточнения проверки покрытия

Лимиты8/12 и8s — обратимые инженерные значения по умолчанию, не предпочтения пользователя. Ответ о числе удилищ/кнопках важнее. Финальный отчёт обязан отдельно оставить аппаратную приёмку хаба ожидающей до идентификации/подключения именно хаба; программные кадры и сборки не доказывают физическую работу OLED/мотора/радио.

## Ответ пользователя2026-11-17

«no buttons». Физических кнопок нет; применяется автоматическое переключение страниц, новыеGPIOне назначаются. Количество удилищ не уточнено; ёмкость8 — настраиваемый инженерный предел, не утверждение о количестве подключённых датчиков.

## Поправка по коду D-HU01

Порог объединения продолжений обязан учитывать максимальныйrepeatMs2000 датчика плюс нормальную задержку свежей выборки; исходные2000мс недостаточны. Повторная инициализацияOLED обязана освобождать ресурсы предыдущего драйвера. Оба условия из независимого ревью исправляютсяF2, пользовательскийфункционал прежний.
