Пользователь: «состояние, калибровка должна быть видна, батарея должна быть видна. ESP Now должен быть виден. Кнопка калибровки, кнопка теста ... включения охраны ... Serial CSV тоже на этой же странице ... остальные данные можно скрыть». Подтверждение: «Да, делай».

Дополнение: «Также страницу датчика надо тоже переработать ... названия не помещаются на экран телефона».

## Принято в работу UI01

- Основная страница: состояние, калибровка, батарея, ESP-NOW; действия калибровка/тест и переключатели ARM/Serial CSV.
- Остальная телеметрия доступна в закрытых по умолчанию подробностях.
- Страница детекции также помещается на телефоне; точные значения порогов доступны.
- Проверка ширины 320/390 px; русские и английские подписи, сохранение диапазонов и обработчиков.
- Не изменять алгоритм детекции, калибровку, pins и протокол. Перепрошивка отдельным шагом после проверки сборки.

## Результаты текущего физического прогона

USB CSV реально получен, около 103 выборок/с. Одиночное касание распознано, фон затем восстановился. Касания стола вызвали события; полевую эффективность это не доказывает.
При небольшом изменении ориентации возникла постоянная тревога, сбрасываемая снятием/включением охраны. При снижении UP/TILT с25/45 до5/5 градусов записаны ARMED → SUPPRESSED → SETTLING → ARMED; события до/после подавления остались. Эти проблемы алгоритма пока не исправлены.
Скриншот старой калибровки показывает rejected: movement при старом сообщении о сохранении; нельзя считать эту попытку успешной. Текущее состояние каждой калибровки отдельно не установлено.

Исполнитель mobile_status_ui. Узкое исправление интерфейса выполняем одним таском; общий следующий этап радио/хаба остаётся открытым, не объявляется завершённым.

Дополнение по дублированию: пользователь заметил одинаковые Status/Diagnostics. В исходнике подтверждено `page==0||page==3`. В UI01 объединяем их в Status с подробностями; меню остаётся Status/Sensor/Settings.
