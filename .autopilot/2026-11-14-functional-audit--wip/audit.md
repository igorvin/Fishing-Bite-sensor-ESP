# Полный функциональный аудит

Дата: 2026-11-14. База: commit 00e8e81. Две прошивки: датчик src/main.cpp и хаб ESP_HUB/src/main.cpp. Источники проверены двумя независимыми проходами: алгоритм/эффективность и система/библиотеки. Код проекта не изменён. Приоритеты: P1 — нарушает основную функцию; P2 — существенно ухудшает надёжность/управление. Дефект, ограничение и аппаратно зависимый риск ниже разделены явно.

## Вывод для конкретного применения

Пока это перспективный прототип сигнализатора движения, не подтверждённый полевой сигнализатор поклёвки. На небольшой силе движения у текущего алгоритма есть математическая слепая зона. Наблюдение пользователя о слабых толчках согласуется с этой слабостью, но не доказывает единственную причину: нужны сырой XYZ, проверка IMU и механики крепления.

Датчик планируется на средней части бланка, не у кончика. Передача движения в это место зависит от длины/жёсткости удилища, положения опор, крепления, массы корпуса и направления нагрузки. Нельзя обещать одинаковую чувствительность на всех снастях или ловлю любого натяжения. Сначала проверить, есть ли измеримый сигнал относительно шума именно в выбранной точке. Если сигнала почти нет, программная фильтрация его не восстановит: сравнить место/крепление, массу, либо иной физический способ регистрации.

Система в текущем виде не готова к обещанию «поставил и не пропустишь»: возможны внешне нормальная охрана без IMU, отсутствие пробуждения, потеря единственного радиоуведомления и подавление полезного сигнала перемещением удилища. Это не означает бесполезность выбранного IMU: сначала нужно исправить управление, наблюдаемость и признаки детектора.

## Что именно видит алгоритм

В src/main.cpp:1252–1255 вычисляется d = abs(norm(accel) - baseline). Направление потеряно. При тяжести (0,0,1) g и поперечном ускорении x имеем d=sqrt(1+x²)-1. Для x=0.1 g получается 0.00499 g, что меньше даже минимального UI-порога 0.02 g; для дефолтных 0.15 g потребуется примерно 0.568 g поперечного ускорения. Это расчёт при фиксированной базе 1 g, не измерение силы реальной поклёвки.

| Поперечное ускорение, g | Видимый сигнал, g |
|---:|---:|
| 0.02 | 0.00020 |
| 0.05 | 0.00125 |
| 0.10 | 0.00499 |
| 0.15 | 0.01119 |
| 0.30 | 0.04403 |

Медленный поворот почти не меняет модуль тяжести. Гироскоп в текущем алгоритме не используется. Снижение единственного порога увеличит реакцию на фон и не устранит зависимость от направления. Нужны сравнение с динамическим вектором после оценки тяжести, оконные признаки и отдельная оценка фонового шума; победитель выбирается по записям.

## Ограничения и решения для переработки

| ID | Подтверждённое свойство / риск | План |
|---|---|---|
| L01 | Модуль ускорения теряет направление; медленные изменения/поперечные слабые толчки могут теряться | XYZ recording и сравнительный replay; не обещать абсолютную чувствительность |
| L02 | EMA базы .999/.001 обновляется даже в движении; τ≈10с при100Hz. Искусственная ступень1→1.3g опускает d ниже.15 через~693 выборки | Явные правила quiet-only adaptation и event freeze, оценка на данных |
| L03 | IMU104Hz, poll≤100Hz, нет FIFO/DataReady/freshness, блокирующие операции создают gaps | Измерять dt/missed, выбрать DRDY/FIFO либо контролируемый polling по реальному спектру |
| L04 | auto-disarm до bite detection может спрятать событие; stable base проверяет модуль, не variance направления | Отдельный MotionSuppressed с журналом и возвратом, правило приоритета события/подъёма; решение пользователя уже принято |
| L05 | Один mailbox теряет одновременные события даже без межъядерного race | Bounded queue, overflow counters, справедливая обработка нескольких удилищ |
| L06 | Нет protocol version/stableID/session/seq/ACK/heartbeat; send callback status игнорируется | Версионирование, ACK/retry/dedup; heartbeat/online UI с отдельным бюджетом энергии |
| L07 | Имя TX≤15байт, не15символов; UTF8 может обрезаться; имя не надёжный ID | ID отдельно от display name; bounded valid UTF8 |
| L08 | Default open AP и unset Settings auth; доступны OTA/file endpoints через библиотеку | Настройка защиты/окно pairing; не хранить придуманные пароли; отключить ненужные endpoints |
| L09 | Нет flush перед sleep, autocommit10s; latch hold и powerOff при USB не доказаны | Explicit commit-before-sleep; физические power/wake/USB/wdt tests |
| L10 | Гироскоп и temp читаются, но не используются; gyro по умолчанию включён библиотекой | Выключить ненужный gyro только после проверки поддержки/потребления или обосновать его признаки |
| L11 | Alerts считает импульсы, не независимые поклёвки | Разделить events, pulses, sent, acked, drops; не использовать Alerts как ground truth |
| L12 | Floating stable/libs, IDF-major guards не гарантируют совместимости callbacks | Pin известных версий и CI; см. libraries.md |
| L13 | Ёмкость, ток, герметичность, дальность, тип снасти и IMU не подтверждены | Не публиковать проценты/часы/метры без измерений; validation.md |
| L14 | ESP32-S3 Zero Mini не имеет профиля в проекте | Основной выбран XIAO S3; остальные платы отдельный объём после подтверждения |

## Безопасность и достоверность выводов

Не найдено оснований называть открытый AP «утечкой секрета»; это конфигурация доступа, которую нужно согласовать. Отказ/просадка питания, held-GPIO и тип зуммера нельзя полностью подтвердить по C++ без схемы и измерений. Имитированные толчки не считать реальными поклёвками. Никаких обещаний «95% точности» из одного кода.

## Первичные источники

- ADC: https://docs.espressif.com/projects/arduino-esp32/en/latest/api/adc.html — raw некалиброван, millivolts калиброван, диапазоны SoC различаются.
- ESP-NOW: https://docs.espressif.com/projects/esp-idf/en/v5.2.4/esp32/api-reference/network/esp_now.html — MAC success не доказывает обработку приложением; рекомендованы ACK/sequence при необходимости надёжности.
- SMP: https://docs.espressif.com/projects/esp-idf/en/v4.3.4/esp32/api-guides/freertos-smp.html — отключение interrupts только локальному ядру.
- Фактические исходники Adafruit LSM6DS4.7.4, Settings1.4.3 и Arduino3.3.12 из чистых временных сборок; upstream сведения и решения по зависимостям — libraries.md.
