# Ревью схемы датчика и два варианта Rev B

Статус: черновики, не выпуск в производство. Дата: 18 ноября 2026.

## Решение пользователя

«На плате, которая открыта, давай ты её сделаешь как S3, и также мы сделаем второй вариант с платой с датчиком C3».

В EasyEDA текущий лист назван Sensor S3 - Rev B - DRAFT. Для C3 клонирован только лист датчика, создана отдельная схема и отдельная Board Sensor C3 - Rev B - DRAFT. Исходный проект экспортирован до изменений: /Users/macbook-air/Documents/ChatGPT/Fishing bite sensor/Fishing-Bite-Sensor-original-before-S3-C3-review.epro. Копия содержит старые ошибки и служит историческим исходником.

## Исполнение IMU: решение пользователя

Пользователь выбрал готовый модуль LSM6DS3 со стенда для текущих вариантов S3 и C3. В дальнейшем требуется перейти на отдельную микросхему ради уменьшения размера. Это отдельная аппаратная ревизия после проверки модульного прототипа.

Ближайший порядок: идентифицировать конкретный модуль и его питание/подтяжки; закончить символы XIAO, батарею и безопасные GPIO; выбрать реальные нагрузки и компоненты; проверить электрические соединения; собрать и проверить прототип с модулем; затем проектировать PCB. Переход на IC требует новой обвязки, посадочного места, проверки питания, монтажа и повторной аппаратной приёмки. Программный интерфейс IMU желательно сохранить, но эквивалентность шума и чувствительности подтвердить повторными измерениями. Размеры платы и корпуса ещё не зафиксированы.

## Уже исправлено и прочитано повторно

В ОБОИХ черновиках:

- Разорвана ошибочная связь +5V с затвором Q3, R6.1 и R7.2. Затвор соединён только с R7.2 и R6.1; источник Q3 и R6.2 — GND. Питание анода зелёного LED сохранено отдельно.
- Исправлены названия портов I2C у IMU: SDA = U4.D4 + U2.5; SCL = U4.D5 + U2.4. Соединения подтверждены через повторное focused-чтение netlist после сохранения через редактор.
- Изменения сохранялись в EasyEDA. Старое PCB не синхронизировалось.

MCP нюанс: ответ success для изменения net у legacy-маркера не доказывает сохранение имени. Движение/удаление такого маркера мост блокирует. Имена менялись через native UI, затем проверялась фактическая сеть. Не обходить эти ограничения raw exec.

## Подтверждённые проблемы, которые ещё надо исправить

| Приоритет | Проблема | Исправление |
|---|---|---|
| P1 | U4 — общий Seeeduino XIAO SAMD, не точный ESP32-S3/C3; BAT-контактов нет | Точные символы и посадочные места каждого XIAO, с отдельными BAT+/BAT- |
| P1 | Батарея соединена только с делителем, не с питанием XIAO | Защищённая 1S батарея к BAT/GND конкретной платы; USB VBUS отдельно |
| P1 | Нагрузка питается от +5V, которого может не быть при питании от батареи | Выбрать нагрузку на 3.3V либо явно проектировать преобразователь с учётом тока; не считать 5V доступным автоматически |
| P1 | Схема и существующая прошивка имеют разные назначения GPIO | Новые отдельные профили Rev B; существующий стенд не перепрошивать под новую разводку |
| P1 | ARM на D6 текущей прошивки не поддерживает deep wake ни у C3, ни у S3 | Кнопка на wake-capable GPIO, внешняя подтяжка, новая логика сна |
| P1 | Параметры GY-LSM6DS3 breakout и его стабилизатора/подтяжек неизвестны | Выбран готовый модуль со стенда; установить его точное исполнение, питание, уровни, подтяжки, CS/SA0 |
| P1 | Зуммер без точной модели, напряжения и типа | Выбрать конкретный MPN, подтвердить ток и драйвер; диод нужен по характеру нагрузки |
| P1 | LED2 GREEN и LED3 RED имеют одинаковый красный MPN; footprint расходится с MPN | Проверить BOM и посадочные места, подобрать реальные разные LED |
| P2 | 150 ohm для LED от 5V может давать около 20mA | Рассчитать резисторы по выбранным LED и экономичному току |
| P2 | Значение D1 1N4001 расходится с MPN 1N4007W | Согласовать тип, корпус, полярность и необходимость диода |
| P2 | Делитель батареи сейчас на D0, прошивка читает D2 и управляет D0 как hold | Перенести в Rev B на D1 и обновить отдельный профиль прошивки |
| P2 | Нет подтверждения тока зарядки для конкретной ревизии XIAO и батареи | Сверить ревизию платы и паспорт элемента, не обещать безопасность по одной ёмкости |

Старое соответствие: зелёный D1 против D7 в прошивке; красный D2 против D8; кнопка D7 против D6; делитель D0 против D2. Питание hold/powerButton в коде не имеет показанной схемы фиксатора питания. Такая схема не совместима с текущей прошивкой.

## Рекомендованное распределение Rev B, пока проектное

Рекомендация проверяющего: одна кнопка ARM/снятие/сон/пробуждение; без отдельного внешнего фиксатора питания, которого нет на исходном листе. Это ещё не реализовано на схеме и в прошивке.

| Назначение | XIAO S3 | XIAO C3 |
|---|---|---|
| Батарея ADC | D1 / GPIO2 | D1 / GPIO3 |
| ARM → GND | D3 / GPIO4 | D3 / GPIO5 |
| SDA / SCL | D4 / GPIO5; D5 / GPIO6 | D4 / GPIO6; D5 / GPIO7 |
| Зелёный LED | D7 / GPIO44 | D7 / GPIO20 |
| Красный LED | D6 / GPIO43 | D6 / GPIO21 |
| Зуммер | D10 / GPIO9 | D10 / GPIO10 |
| Резерв INT1 IMU | D0 / GPIO1 | D2 / GPIO4 |

Обходятся strapping GPIO: S3 D2 не использовать; C3 D0/D8/D9 не использовать. D6/D7 совпадают с UART0 — диагностика через native USB; красный LED может мигнуть при ROM-загрузке. Зуммер намеренно не на UART. Резервирование INT1 не означает, что motion wake реализован: текущая прошивка опрашивает IMU и требует отдельной доработки. Для сна надо проверить полярность и фиксацию прерывания IMU и подходящий wake API каждой платформы.

100k + 100k и 100nF в делителе можно сохранить: при 4.2V ADC видит 2.1V; ток делителя 21uA. Требуются правильная attenuation и калибровка по мультиметру.

## Следующий порядок

1. Исполнение выбрано: готовый модуль со стенда. Подтвердить его точную плату и электрическую обвязку; IC оставить для следующей компактной ревизии.
2. Зафиксировать точные ревизии и корпуса XIAO, BAT-контакты; для IC — BOM и обвязку по даташиту.
3. Выбрать подходящий малопотребляющий зуммер и LED, исправить питание и зарядку.
4. Внести Rev B назначения GPIO, кнопку, тестовые точки и развязку питания; при необходимости зарезервировать INT1.
5. Повторное электрическое ревью, ERC и проверка BOM/footprints отдельно S3 и C3.
6. Только после этого PCB: размеры корпуса/крепление, антенная зона, USB, аккумулятор, механическая передача вибраций, DRC.
7. Отдельные firmware-профили Rev B и стендовые проверки. Автономность и эффективность на удилище подтверждать измерениями, не расчётом номинальной ёмкости.
