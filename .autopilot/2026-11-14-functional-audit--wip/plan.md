# Полный план переработки

Статус: план, реализация не начата. База00e8e81, 2026-11-14. Главная цель пользователя — слабые движения на средней части бланка, XIAO ESP32-S3, небольшой аккумулятор, веб-настройка, временное подавление при перемещении с автоматическим возвратом. Выбор хаба, точный IMU, размеры/ёмкость батареи и допустимые false positives ещё открыты.

## Таск 01 — Исправление основы датчика и безопасное выделение модулей

Зона: sensor src, BoardProfile, State/Output/Imu/Config modules, platformio config, README/pinout и targeted host tests. Сначала исправить воспроизводимые ошибки, затем перенести код с сохранением исправленного поведения. Реестр: F01–F03,F07–F12,F14–F20,F21; L03,L09,L10,L12,L14. Hub deps/ADC относятся к таску02.

1. Зафиксировать поддержанную XIAO S3 конфигурацию, известные совместимые версии платформы/прямых и существенных транзитивных libs; минимальный reproduce build. Другие env не объявлять поддержанными без сборки и pin-test.
2. Явные Boot/Disarmed/Settling/Armed/MotionSuppressed/Fault/SleepPending. Один владелец времени и переходов; хранить timestamps входа, учитывать rollover.
3. Beep/pulse без delay; output tick независимо от armed/IMU. Исправить passive tone и validate PWM attach; проверить старые core/channel differences.
4. IMU проверяемое чтение/health/recovery; отказ не выдаётся за готовность. Модель/WHO_AM_I/адрес фиксируются по железу.
5. Wake-compatible pin и проверка API return, flush перед sleep, latch/USB/reset behaviour. Переподключение GPIO — физическая операция по проверенной схеме, не автоматическая правка наугад.
6. Настройки draft→validate→apply→persist; menu reload; строгий MAC; ограничения SSID/password; live radio reconfigure с контрактом таска02; last-known-good после отказа сохранения.
7. ADC калибровка sensor; отделить проценты от фактических mV и low-event pending.
8. Выделить модули из main.cpp, не размножая мелкие обёртки; чистое ядро детектора для replay. Зафиксировать реальное поведение и убрать ложные обещания Smart Learn.

Готово: регрессии старых дефектов проходят; на выбранной плате подтверждены wake/power/tone/IMU fault/reconnect/UI persist. Если платы недоступны, явно «host готов, hardware pending», а не полная готовность.

## Таск 02 — Радиопротокол, хаб и доставка

Зависит от границ таска01. Зона: common protocol, RadioLink обоих устройств, HubApp/display/motor/battery, hub env/deps и transport tests. Реестр F04–F06,F13,F15–F17; L05–L08,L11–L12.

1. Исправить deps хаба: OLED libs только там где нужны, убрать IMU/Settings из хаба если он их не использует, исправить несуществующий Adafruit LSM6DS3 identifier.
2. Единый wire contract с version/deviceID/session/seq/event/battery/flags и явными границами строк. Проверка length/version/type/range/isfinite; неизвестное отвергается без crash.
3. RX callback складывает в bounded queue; loop обрабатывает. Overflow и drops наблюдаемы; политика нескольких одновременных удилищ явная.
4. ACK/retry/backoff/dedup и low-battery pending до результата; heartbeat и индикация потери связи — согласовать интервал с малым аккумулятором.
5. Радио/мотор запускаются независимо от OLED. Отказ экрана — degraded mode, не мёртвый хаб. Валидировать мотор/питание на реальном хабе после выбора платы.
6. Миграция: сначала хаб понимает старый и новый форматы; затем датчик; старый удалить только после проверки комплекта. Если решено обновить оба устройства сразу, это решение записать отдельно.
7. Access policy AP/config/OTA/files: безопасная настройка без придуманного постоянного пароля; ненужные endpoints выключить, настройки и firmware update защитить.

Готово: injected loss/reorder/duplicate/invalid packet/receiver reboot не создают повреждённых данных и повторных уникальных событий; сценарий fail-offline→online виден; загрузка хаба без экрана принимает и вибрирует. Статистика разделяет source events/sends/ACK/pulses.

## Таск 03 — Измеряемая чувствительность и воспроизведение

Зависит от sampler/interfaces таска01; может идти параллельно таску02 только по разным файлам. Зона: debug capture/replay/test fixtures и минимальная диагностическая поверхность UI. Цель — сделать проблему слабых движений измеримой, а не просто добавить ещё один слайдер.

1. Кольцевой RAM-буфер raw XYZ, gyro если нужен, timestamp/dt, range/ODR, baseline/признаки/порог/state/quality; pre/post event контекст. Не писать каждую выборку во flash.
2. Пакетная выгрузка/serial с оценкой влияния логирования на sampling; обезличенные fixtures и replay на ПК через тот же detector core.
3. Стендовая серия с одним креплением: фон, слабые повторяемые толчки/потяжки разных направлений, повернуть sensor и повторить; отдельно реальные движения удилища и имитации леской.
4. UI показывает сигнал, фон, threshold, actual rate/gaps и health; калибровка отклоняется при движении, результат сохраняется явно и проверяется после reboot.
5. Контрольный старый magnitude algorithm; единицы g/mg и смысл «больше чувствительность» не инвертированы скрыто.

Готово: запись можно загрузить повторно и получить те же решения; видны все пропуски выборок; есть quiet и weak-motion корпуса данных. Если signal/noise у середины бланка непригоден, остановить выбор фильтра и проверить механику/место.

## Таск 04 — Новый детектор, временное подавление и итоговая настройка

Зависит от01 и03. Зона: BiteDetector/RodMotionGate/UI calibration, fixtures и инструкции. Радиоконтракт не менять без таска02.

1. Сравнить magnitude baseline с вектором динамического ускорения (оценка тяжести), оконными RMS/energy/peak/duration и ограниченным hysteresis. Полосовые фильтры/gyro — только при подтверждённом выигрыше на записях.
2. Исправить trigger attack/release: определить порог входа/выхода, минимальную длительность, cooldown и continuous события; убрать скрытый хвост накопителя255.
3. Noise calibration: робастная оценка quiet-фона, явная минимальная абсолютная чувствительность, ограниченная адаптация; не поглощать событие baseline и не переобучаться на каждом движении.
4. Пользовательское Armed→MotionSuppressed→Settling→Armed с верификацией стабилизации по variance/движению и observable reason. Manual Disarmed и Fault не возобновлять автоматически. Сильная поклёвка не должна молча теряться из-за неясного приоритета gate.
5. Понятная web-шкала/порог, окно диагностики; настройки проходят validate/persist/reboot. Автокалибровку шума не называть обучением распознаванию рыбы.
6. Выбор на обучающих/настроечных сессиях, итоговая оценка на отложенных целых сессиях. Полевая донастройка не превращает контрольный набор в настройку.

Готово: есть сравнительный отчёт на одном наборе с TP/FN/FP, временем слежения и задержкой; новый алгоритм принят только если улучшает согласованную цель без скрытого роста ложных тревог/энергии. Синтетические толчки подтверждают реакцию на движение, не полевую точность.

## Проверки и итоговая приёмка

Точечные host тесты соответствуют реальным багам: stale now/rollover, pulse timeout во всех состояниях, transitions/manualDisarm/fault, angle wrap, attack/release tail, invalid config, packet bounds/ASan и transport loss/duplicates. Чистые сборки поддержанной матрицы закреплённых версий. После каждого функционального пакета — независимое ревью изменённого кода; в конце полное ревью и hardware/field checklist из validation.md.

Финальный критерий: не «все функции компилируются», а детектор стабильно замечает согласованные слабые события при приемлемом уровне ложных тревог и доставляет их на хаб, оставаясь включённым нужное время. Численные цели до измерений и решения пользователя остаются открытыми.

## Оценка объёма и порядок начала

Предварительно около5–9тыс. изменяемых строк с host tests/diagnostics, 4 крупных таска; это диапазон планирования, не обещание срока. Больше всего неизвестности в железе, сборках/драйвере и реальных данных. Сначала таск01 и ранняя запись слабых движений из03; выбор новой библиотеки или закупка нового IMU только по результатам проверки. Измерять полный ток уже на первом рабочем стенде: маленький аккумулятор может ограничить архитектуру раньше, чем фильтры.

Нет автоматического перехода к реализации из этого документа. Все таски ниже — будущая работа, не отчёт об исправлениях.
